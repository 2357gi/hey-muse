# Jevによる天気・予定の言い換え

Echo Showのローカル音声認識結果をJevで分類し、天気画面または母艦カレンダーの予定欄に振り分けます。APIキー、予定の内容、カレンダーID、機器情報はJevの入力に含めません。送信するのは発話の文字列と固定の分類質問です。

## 対応範囲

| 依頼 | 表示・応答 |
| --- | --- |
| 「雨降りそう？」「傘いる？」 | 設定地域の今日の天気・降水確率 |
| 「明日傘持っていったほうがいい？」 | 設定地域の明日の予報 |
| 「この先一週間の天気を知りたい」 | 今日から7日間の天気 |
| 「今日あと何かあったっけ？」 | 今日の残りの予定 |
| 「明日のスケジュール確認して」 | 明日の予定 |
| 「今週のスケジュールを見たい」 | 今週の日曜までの残りの予定 |
| 「今日から7日分の予定を見せて」 | 今日を含む7日間の残りの予定 |

傘の質問には実際の予報を返します。Jevが天気や予定を生成することはありません。予定は既存のキャッシュを使い、進行中・複数日にまたがる予定も期間に含めます。絞り込みは2分で通常表示へ戻ります。未取得・取得失敗・10分より古い情報を「予定なし」とは回答しません。取得上限の24件に達している場合も、全件数や予定の不在を断定しません。

引用・否定・仮定、予定の追加/変更/削除、家電操作、複数の依頼、別の地域、特定の予定やカレンダー、午後などの時間帯指定、週末や来月、「明日は？」だけの文脈依存の発話は対象外です。日付未指定は、天気か予定への依頼が明確なら今日として扱います。

既存の定型句はJevを呼ばず処理します。家電の定型操作・保留判定も既存の経路を使います。それ以外の発話について、Jevに「対象範囲の読み取り依頼か」と「どの表示先か」を一度に問い合わせます。両方の確率が既定の0.85以上で、許可済みの表示先に一致する場合だけ採用します。曖昧な結果、未設定、API障害、不正な応答は元の文字起こしとチャットIDを保って通常のMuse会話へ戻します。キャンセル時は表示もMuseへの送信も行いません。

## 有効化

この機能は既定で無効です。ローカル文字起こしと[母艦ブリッジ](../tools/mothership/README.md)が必要です。画面への連携はEcho Show向けで、Spot/Dotの既存経路は維持しています。

1. 母艦ブリッジのプロセスに `TYPESAFE_API_KEY` を設定するか、リポジトリ外のキーだけを保存したファイルを `TYPESAFE_API_KEY_FILE` で指定します。両方ある場合は環境変数のキーを優先します。値をコードや起動引数に書かないでください。
2. 母艦の `tools/mothership/home-local.json` に次を追加します。

```json
"jev": {
  "enabled": true,
  "model": "jev-1.14.0",
  "minimum_probability": 0.85,
  "timeout_seconds": 1.5
}
```

3. Echoの `/data/misc/techo5/idle-home.json` に `"Jev": true` を追加します。既存の `URL`・共有鍵・シーン設定を維持します。
4. 更新したEchoバイナリと母艦ブリッジを起動します。母艦側の `enabled` またはEcho側の `Jev` をfalseにすると、Jevを使わない経路へ戻ります。

Echoと母艦の間は既存のAES-GCM/HMAC、nonceと時刻の検証を使います。`/echo-intent/v1` は分類専用で、シーン実行・カレンダー変更の操作を受け付けません。Echo側は全体を2.5秒で打ち切り、APIへの自動再試行や母艦の起動待ちは行いません。母艦が眠っていれば通常の会話へ戻ります。

## 検証

2026年11月5日、`jev-1.14.0`、閾値0.85で実APIを評価しました。

| 評価セット | 期待どおり | 対応対象を通常会話へ戻した数 | 別の表示先への誤振り分け | API障害 | 応答中央値 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 開発用40例 | 39 | 1 | 0 | 0 | 0.185秒 |
| 質問文の調整に未使用の24例 | 23 | 1 | 0 | 0 | 0.179秒 |

通常会話へ戻ったのは「今週あとどんな予定ある？」と「一週間分の天気予報が見たいんだけど」です。対象外の32例はすべて採用されませんでした。これは固定例文での結果で、実機の文字起こし精度や利用全体の正答率を保証するものではありません。モデルや質問文の変更時は再評価してください。

```text
python -m unittest discover -s tools/mothership -p "test_*.py"
python tools/mothership/evaluate_jev.py --model jev-1.14.0
python tools/mothership/evaluate_jev.py --model jev-1.14.0 --cases tools/mothership/jev_cases_holdout.json --output tools/mothership/jev-evaluation-holdout.json
```

通常の自動テストはAPIの偽応答を使います。後ろの2コマンドは明示的な実API評価で、環境変数のキーを使います。評価用の固定例文だけを送信し、画面・家電・カレンダーへの操作は行いません。結果ファイルはGit対象外です。

Goのテストでは、元の発話・サイドチャットの維持、キャンセル、認証済み通信、改ざん、未知の表示先、締切、日付境界、取得失敗時の表示を確認します。Pythonでは、未設定、低確率、形式不正、APIの401/429/503、タイムアウト、HMAC、暗号化、再送、分類以外の操作の拒否を確認します。

APIの形と並列判定は[TypeSafe API](https://docs.typesafe.ai/api/system-one)、[Choice](https://docs.typesafe.ai/primitives/choice)、[Noul](https://docs.typesafe.ai/primitives/noul)に従います。確率とconfidenceの違いは[公式の説明](https://docs.typesafe.ai/confidence)を参照してください。
